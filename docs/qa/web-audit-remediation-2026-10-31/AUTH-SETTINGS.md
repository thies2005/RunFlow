# Auth and settings remediation

- F05: Provider URL, key and model have persistent labels and distinct names/autocomplete hints; malformed, non-HTTPS or credential-bearing URLs disable test and save and are guarded in the handlers. HTTPS matches the server's provider restriction. Blank URL selects the existing OpenAI default. Password managers can disregard autocomplete hints, so autofill prevention is not guaranteed across products.
- F12: Desktop settings subpages now use a wider named shared modal with scrolling. Biometrics explains profile save, immediate display changes and separate calibration saves. Switch and selection states are exposed for the touched controls. Mobile retains its existing full-screen settings panel.
- F13: Full AI Coach explains administrator approval and provides View AI access when denied; approved users see setup language. Provider configuration appears only when access is granted, and provider test requires an intentionally entered key. Loading errors are distinct from denied access in both chat and settings; a saved personal key no longer overrides the AI enabled switch in chat.
- F14: Recovery uses the named shared dialog and associated email/code/password labels. Shared modal traps tab focus, handles Escape, restores focus and retains body scroll lock for stacked dialogs. Only the top dialog handles Escape or native back, and deferred initial focus respects the top dialog.
- F15/F16/F19: Mobile login introduction is compact; login and registration share a text wordmark and multi-sport copy. Forms have persistent labels, password reveal controls and upfront registration requirements matching the server, including special character and forbidden patterns; recovery describes the same rules. Footer version is coordinator-owned.
- F06/F17: Named AI chat controls, settings switches and selected states; increased some small helper labels. Shared text contrast tokens are coordinator-owned.

Validation: `npm test -- --runInBand src/components/__tests__/AiSettingsModal.test.tsx src/components/__tests__/Modal.test.tsx` passed (2 suites, 3 tests). The tests exercise rejection without a provider request and dialog naming, Tab wrapping, Escape, focus restoration, and stacked-dialog scroll locking in jsdom. In the local browser, email sign-in showed persistent labels, registration showed its requirements before entry, and recovery opened as a named dialog; Shift+Tab wrapped to Cancel, and Escape returned focus to Forgot password. Password-manager behavior, screen-reader announcement, real registration/recovery delivery, all entitlement/provider combinations, native back, mobile keyboard and 200% zoom were not verified by this work. The focus tests mock element visibility.
